# Standalone figure regeneration

```bash
python Modules/Analysis_Figen_block/figures/run_figures.py \
  --config Modules/Analysis_Figen_block/figures/figures.in
```

Use this runner when figures need to be regenerated independently. Normal AHC
and structural module runners already generate the figures coupled to their
analysis products, so running this module again is optional.

Available blocks are AHC physicochemical/trajectory, chemical-space,
physicochemical last-window, the base PR/PPS interaction hotspot, full/last
hotspot, top-candidate hotspot, and own/opposite hotspot. At least one must be
ON. Only inputs for enabled blocks are required. `interaction_hotspot` consumes
the residue and interaction-type prevalence tables generated by
`interaction_result_analysis`, six Fpocket atom PDB files, and the automatically
generated PR/PPS reference-interaction CSV.

Crossdocking density and selectivity figures are not duplicated here. Their
canonical implementation is `Modules/Crossdocking/CompletedAnalysis/figures`.
The old copies are preserved under `Analysis_Figen_block/bins/legacy_crossdocking_figures`.

All generated figures use collision-safe names: an existing file is retained
and the new figure receives `_1`, `_2`, and so on. Relative paths resolve from
`figures.in`.

## Current production inputs

- Chemical-space figures consume the cached table generated by completed AHC
  analysis. The configured cache run ID must match that upstream result.
- The base interaction hotspot consumes `residue_prevalence.csv`,
  `interaction_type_prevalence.csv`, six selected Fpocket pocket atom files,
  and the pipeline-generated `reference_interactions.csv`.
- Optional hotspot variants require their own specialised input tables. Empty
  paths are valid only while the corresponding block is OFF.

Comparative figures use PPS red `#D9534F` and PR blue `#2878B5`. Figure output
belongs below `work_results/Figs/<feature>/<run_id>/`. Review the underlying CSV
and manifest rather than interpreting the image alone.

## Configuration reference

Shared options:

| Key | Required | Default | Meaning |
|---|---:|---:|---|
| `results_root` | Yes | — | Output root whose final directory name is `work_results`. |
| `run_id` | Yes | — | Identifier used in all enabled figure output directories. |
| `resume` | No | `OFF` | Controls run-directory reuse; individual figures are always collision-safe. |
| Figure switches | No | `OFF` | Set one or more of `ahc_physchem`, `chemical_space`, `physchem_last_window`, `interaction_hotspot`, `hotspot_full_last`, `hotspot_top_candidates`, or `own_opposite` to ON. |

### AHC physicochemical and trajectory figure

Required when `ahc_physchem=ON`: `ahc_input`, `ahc_job_name`, and `reference`.

| Key | Default | Meaning |
|---|---:|---|
| `ahc_input` | — | One completed AHC `scores.csv`. |
| `ahc_job_name` | — | Population label displayed in outputs, normally `PR` or `PPS`. |
| `ahc_threshold` | unset | Optional docking-score cutoff drawn/applied by the workflow. |
| `reference` | — | Reference descriptor CSV. |
| `ref_keys` | `OM` | Comma-separated reference identifiers to display. |
| `descriptors` | workflow default | Descriptor columns to plot, such as `desc_MolWt,desc_NumRotatableBonds,desc_CLogP`. |
| `mw_upper_bound` | automatic | Explicit molecular-weight x-axis maximum; blank uses the data-derived bound. |

### Chemical-space figure

`chemical_space=ON` requires `cache_path`, pointing to an existing embedding
CSV/CSV.GZ generated by completed AHC analysis. This runner plots the cache; it
does not recalculate UMAP or t-SNE.

### PR/PPS last-window comparison

`physchem_last_window=ON` requires `pr_input`, `pps_input`, and `reference`.
`last_n` defaults to 50. `pr_threshold` and `pps_threshold` are optional
population-specific docking cutoffs.

### Interaction hotspot figures

| Switch | Required keys |
|---|---|
| `interaction_hotspot` | `interaction_residue_csv`, `interaction_typed_csv`, `interaction_pocket_files`, `interaction_reference_csv` |
| `hotspot_full_last` | `full_csv`, `last_csv`, `typed_csv`, `pocket_files`, `reference_csv`, `denominators` |
| `hotspot_top_candidates` | `top_own_csv`, `top_opposite_csv`, `top_typed_csv`, `top_pocket_files`, `top_reference_csv`, `top_denominators` |
| `own_opposite` | `ownopp_prevalence_csv`, `ownopp_typed_csv`, `ownopp_pocket_files`, `ownopp_reference_csv`, `ownopp_denominators` |

Pocket mappings use comma-separated `LABEL=path` assignments. Labels may
contain spaces:

```ini
interaction_pocket_files=PPS P2=/path/pocket2_atm.pdb,PR P11=/path/pocket11_atm.pdb
```

Denominator mappings use positive integer counts:

```ini
denominators=PPS=205,PR=197
```

The hotspot runner maps residues onto the supplied Fpocket atom files and uses
the reference-interaction CSV for contextual markers. Pocket IDs are specific
to a particular Fpocket run and must be updated when the receptor or Fpocket
result changes.

## Input and output rules

- Only enabled blocks validate their inputs; blank placeholders are acceptable
  for disabled blocks.
- Relative paths are resolved from `figures.in`.
- Unknown options and invalid ON/OFF values are rejected.
- This module visualises existing numerical products. It does not regenerate
  missing chemical-space or ProLIF calculations.
- Existing figure names are preserved; reruns allocate `_1`, `_2`, and so on.
